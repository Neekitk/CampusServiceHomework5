# Change Request — релиз v1.9.0

## Общая информация

**Система:** ИС «Умный кампус»  
**Модуль:** Заказ справок (Деканат)  
**Версия релиза:** v1.9.0  
**Связанная задача:** CAMPUS-107  

## Описание релиза

В релизе v1.9.0 выполняется обновление модуля заказа справок деканата.

Основное изменение связано с подготовкой безопасного перехода от поля `Status` к полю `StatusCode`. Дополнительно в контроллер добавлены OpenTelemetry-теги для формирования единого цифрового следа задачи CAMPUS-107.

## Бизнес-цель

Цель релиза — повысить удобство дальнейшей обработки статусов заявок и обеспечить прослеживаемость операций от задачи в Jira до телеметрии приложения.

Использование числового поля `StatusCode` упрощает интеграцию модуля с другими компонентами системы и снижает зависимость от строкового представления статусов.

## Окно обслуживания

Планируемое окно обслуживания:

**Воскресенье, 02:00–03:00 МСК.**

Данное время выбрано из-за минимальной ожидаемой нагрузки на сервисы ИС «Умный кампус». Это снижает влияние возможных ошибок при развертывании на пользователей системы.

## План проведения работ

1. Проверить состояние текущей версии приложения.
2. Создать резервную точку перед развертыванием.
3. Выполнить фазу Expand миграции базы данных.
4. Развернуть версию приложения v1.9.0.
5. Выполнить миграцию существующих данных.
6. Проверить работу основных API-эндпоинтов.
7. Проверить OpenTelemetry-теги CAMPUS-107.
8. Выполнить Sanity-тест.
9. После подтверждения стабильной работы завершить фазу Contract.

## План отката

При обнаружении критических ошибок выполняется возврат на предыдущую стабильную версию приложения.

Команда отката Kubernetes:

```bash
kubectl rollout undo deployment/campus-service -n production
```

После отката необходимо:

1. Проверить состояние deployment.
2. Выполнить основной API-запрос.
3. Проверить журналы приложения.
4. Убедиться в восстановлении стабильной работы сервиса.

## Условия активации отката

Откат выполняется при следующих условиях:

- сервис не запускается после обновления;
- появляются критические HTTP-ошибки 5xx;
- нарушается работа модуля заказа справок;
- обнаруживается некорректная обработка полей `Status` и `StatusCode`;
- после релиза возникают критические ошибки базы данных.

## Branch Protection Rules

Для ветки `main` должны быть установлены следующие правила:

- прямое внесение изменений в `main` запрещено;
- все изменения выполняются через Pull Request;
- перед объединением Pull Request требуется минимум 2 одобрения;
- дополнительно требуется одобрение Tech Lead перед объединением изменений в `main`;
- обязательно успешное прохождение CI/CD-проверок;
- обязательный запуск автоматических тестов;
- Force Push для ветки `main` запрещён;
- удаление защищённой ветки запрещено.
